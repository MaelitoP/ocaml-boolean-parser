# Architecture

## Pipeline

```
string -> Lexer (ocamllex) -> tokens -> Parser (menhir) -> Ast -> Printer | Eval
```

The lexer turns the input into tokens, the parser builds an `Ast.t`, and the AST is consumed either by the printer (back to canonical query syntax or a box-drawing tree) or by the evaluator (against caller-supplied predicates). Lexing and parsing failures are converted once, in the library entry point, into an `Error.t` value carrying a message and byte offsets.

`Boolean_parser.parse` lexes the whole input into a `(token, loc)` list before running the parser, so a lexical error anywhere wins over a syntax error earlier in the input (the spec requires `1.` to report the stray `.`, not the leading number). The parser is fed from that list and the offending token's location comes from it. Syntax errors currently carry the generic message `syntax error`; the spec's `unexpected X, expected Y` wording needs a menhir `.messages` file and is a separate ticket. An input with no tokens reports `empty query` at end of input.

## Module map

Library `boolean_parser` in `lib/`, wrapped as `Boolean_parser`. Filled in as modules land.

| Module | Status | Role |
|--------|--------|------|
| `Loc` | done (T05) | `{ start; stop }` byte offsets, start inclusive, stop exclusive. |
| `Error` | done (T07) | `{ message; loc }`, the only error shape the library exposes. `to_string ~source` renders `line:col: message`, the offending source line and a caret underline; the underline is clipped to that line and is one caret wide for an empty location (end of input). |
| `Tokens` | done (T05) | Generated by menhir `--only-tokens` from `tokens.mly`; the `%token` declarations are the source of truth for the lexer and the parser. |
| `Lexer` | done (T05) | ocamllex rules in `lexer.mll`: whitespace and `#` comments skipped, longest-match operators, `WORD`, `NUMBER` (a `.` joins a number only when a digit follows), quoted strings via a `Buffer` sub-rule. Raises `Lexer.Error of Error.t`; the parser entry point converts it into a `result`. |
| `Parser` | done (T06) | Generated by menhir from `parser.mly` (tokens merged in from `tokens.mly`). Precedence via `%left OR`, `%left AND`, `%nonassoc NOT`; `%start <Ast.t> query`; `%type <Ast.value> value` is required because `Word`/`Phrase` exist in both AST types. No conflicts. |
| `Boolean_parser` | done (T06) | Library main module. Re-exports `Ast`, `Loc`, `Error`, `Printer`, `Eval`, `Tokens`, `Lexer` (the last two so tests can drive the lexer) and defines `parse : string -> (Ast.t, Error.t) result`, the only way to parse. |
| `Printer` | done (T08) | `to_string : Ast.t -> string` prints the canonical query syntax: `AND` `OR` `NOT` keywords, phrases double-quoted with `"` and `\` escaped, numbers and field values via `Ast.value_to_string`. Parentheses only where the precedence table needs them: a child of lower precedence than its parent, or of equal precedence on the right of `AND` / `OR` (the grammar is left-associative). `NOT NOT a` stays unparenthesized. |
| `Eval` | done (T12) | `eval ~word ~phrase ~field : Ast.t -> bool`. Leaves dispatch to the caller: `word w`, `phrase p`, `field name value`. `Not`, `And`, `Or` are OCaml `not`, `&&`, `||`, so `And` and `Or` short-circuit left to right. The library ships no matcher: what a word, phrase or field value matches is entirely the caller's. |
| `Ast` | done (T04) | `value` (field values: word, phrase, number, `<`, `>`, `<=`, `>=`, `N..M`) and `t` (word, phrase, field, `Not`, `And`, `Or`). No source locations, numbers as `float`. Derives `equal`, `pp`, `show` via ppx_deriving; `pp_tree` renders the box-drawing tree from the spec; `value_to_string` renders a field value in query syntax and is shared with `Printer`. |

Executable in `bin/`:

| Module | Status | Role |
|--------|--------|------|
| `Main` | done (T10) | `ocaml-boolean-parser [--format tree or query] [QUERY]` via `Stdlib.Arg`. Reads stdin when QUERY is omitted; prints `Ast.pp_tree` (default) or `Printer.to_string`. Exit 0 on success, 1 on a parse error (rendered with `Error.to_string` on stderr), 2 on a usage error (unknown option, bad `--format` value, more than one QUERY; `Arg.parse` prints the usage and exits itself). Only IO and exit codes live here. |

| File | Status | Role |

## Build

- `dune-project`: `(lang dune 3.19)`, `(using menhir 3.0)`, `(cram enable)`, generates `ocaml-boolean-parser.opam`.
- Dependencies: `ocaml >= 5.1`, `menhir`, `ppx_deriving`, `alcotest` and `qcheck-alcotest` for tests.
- `lib/dune` has `(ocamllex lexer)` and `(menhir (modules tokens) (flags --only-tokens) (explain false))`; `explain` must be off because `--only-tokens` produces no `.conflicts` file. The parser stanza is `(menhir (modules tokens parser) (merge_into parser) (flags --external-tokens Tokens))`: menhir needs the `%token` declarations in the grammar it compiles, so `tokens.mly` is merged in rather than duplicated. It preprocesses with `ppx_deriving.eq` and `ppx_deriving.show`; `test/dune` uses a `(tests (names ...))` stanza, one executable per module under test; modules not listed in `names` (`gen.ml`) are shared by every test executable. Test libraries: `alcotest`, `qcheck-core`, `qcheck-alcotest`. `(cram (deps %{bin:ocaml-boolean-parser}))` in `test/dune` builds the executable before `cli.t/run.t` runs.
- `flake.nix` provides the compiler, dune, ocamlformat and every library above.
- `.github/workflows/ci.yml` runs on pushes to `main` and on pull requests: `cachix/install-nix-action`, then `nix develop --command` for `dune build @all`, `dune test` and `dune build @fmt`, so CI uses the flake toolchain and never touches opam. `dune build @fmt` only checks formatting; `dune fmt` locally rewrites the files.
